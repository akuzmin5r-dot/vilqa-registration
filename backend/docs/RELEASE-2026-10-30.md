# Выпуск после аудита ub-mode

Проверенный бэкап: `backups/2026-10-30-before-ub-fixes` в рабочей папке, вне Git. Сохранены файлы, все ветки Git, семь workflow, реальные определения функций и данные приложения. Это не серверный образ и не экспорт секретов n8n.

Изменения:

1. Опрос клетчатки имеет отдельный бюджет на набор pending-записей; ошибки сети не обрывают расписание. Новые записи и версии запускают новый цикл.
2. Доставка клетчатки имеет отдельную таблицу состояний. Сообщение отмечается отправленным после подтверждения Telegram; неопределённые исходы требуют проверки вместо слепого повтора.
3. Общие функции, актуальные workflow, миграции и тесты находятся в Git. Генератор проверяется перед выпуском; тесты не читают устаревшие draft-снимки.
4. Браузерный сценарий порции обновлён под диалог. Повтор после потери ответа сохраняет request_id и создаёт одну запись.
5. Старые рабочие материалы и SQL сохранены в архиве/истории. Временные среды анализа удалены. Полное удаление maintenance отклонено автоматической проверкой безопасности, поэтому эта папка сохранена как историческая; поддерживаемый код и тесты находятся в backend.

Проверки:8 поддерживаемых наборов, включая браузерный сценарий; SQL-тест очереди с откатом фикстур. Ранее тот же тест на старой функции воспроизводил преждевременную отметку доставки. Установленная схема дополнена без удаления данных. Общие функции встроены в Code-узлы при генерации, без добавления синхронных subworkflow в путь меню.

Откат: републикация сохранённых workflow и возврат frontend-коммита. Новая таблица доставки может оставаться как журнал. Для возврата старой реализации не надо перезаписывать дневник или удалять пользовательские данные.

Полностью устранить неопределённость сетевого sendMessage невозможно без поддержки ключа идемпотентности со стороны Telegram. Неизвестный результат отправки отображается в общем обработчике ошибок и сохраняется для проверки.
